# Android TV 频道目录协议与发布规则

现有采集、频道规范化、HTTP/FFprobe 检测、历史及主备逻辑继续复用。传统 combined.m3u、backup.m3u 等文件行为保持兼容；新 all.m3u 与 channels.json 仅包含显式授权的合格源。无授权时是空目录和仅含 #EXTM3U 的有效订阅。

## 使用许可

config/usage_rights.yml 的 grants 条目包含 streamId、evidenceUrl、purpose、allowed。证据须真实涵盖允许访问、测试、应用使用及公开发布地址的用途。来源 official/community 标记不授予许可。allowed:false 撤销该 streamId；出现互相矛盾的记录时拒绝。当前没有任何可核验许可，不应向目录添加旧社区源。

发布前排除 URL 用户名/密码、fragment、非白名单查询参数、常见令牌路径及 Xtream 账户路径。证据 URL 也不得包含凭据。无法从任意不透明路径自动证明不存在秘密，登记时仍须核对地址语义；不得把删除令牌后无法播放的地址冒充可用源。

## JSON 格式

channels.schema.json 是从运行时严格模型导出的 JSON Schema；自动测试检查二者一致。根字段 schemaVersion=1、minClientVersion=1、generatedAt（UTC ISO 8601）、contentHash、channels。未知字段、无效协议、重复频道或来源 ID、越界指标及摘要不符均拒绝。

频道包含 id、name、group、logo（当前为空字符串）、sources。来源包含 id、url、type（hls/dash/progressive）、score（0至100整数）、resolution、videoCodec、frameRate、lastChecked、originGroup、lastSuccess、availability。未知检测值使用 null；availability 是实际历史成功次数/检测次数，范围0至1。frameRate、availability最多四位小数，整数输出不带小数点。

contentHash 是 **channels 数组本身**的 SHA-256，UTF-8，JSON对象键按字母排序、无空格分隔符、非ASCII字符不转义。数组顺序有意义，generatedAt与版本字段不入摘要；客户端仍必须独立检查版本。Python等效：json.dumps(channels, ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False)。同内容摘要可用作ETag等效缓存标识；不声称静态Pages一定提供特定ETag响应头。

新目录不裁剪为两条备源，保留全部合格且有许可的主备。originGroup按原始域名及HTTP重定向最终域名的连通分量生成；同组不能视为独立源站。不同域名背后同一CDN但没有可观察重定向时，无法证明其独立性。

## 成对发布和回退

发布顺序是写 catalog-versions/<发布ID>/channels.json 与 all.m3u，回读严格校验，然后写稳定兼容副本，最后原子替换 catalog-manifest.json。需要成对一致的消费者应先读取清单，再读取 channels、playlist 相对路径。直接读取稳定 channels.json 的现有消费者仍可使用；两个独立稳定路径之间无法提供跨文件原子读取保证。

清单 contentHash 指向当前摘要，previous指向上一份有效JSON，其同目录all.m3u是对应订阅。changes.added/removed/modified 给出相对上一版本的频道ID变化。版本文件保留，写入或校验失败不会更新清单。稳定副本发生写入错误时尝试恢复；持续磁盘故障下应以未切换的清单和版本文件为准。本轮所有探测失败时，如果原目录全部源仍获许可，保留原有效目录和原时间；撤销许可时不沿用旧目录。

## 检测和评分的实际边界

HTTP不仅检查200：拒绝HTML、空响应、占位视频与VOD清单；HLS递归选择一个变体，顺序采样媒体清单最近至多三个分片。FFprobe短时采样识别音视频轨、编码、分辨率、帧率、可观测码率和视频时间戳持续性。并发和超时沿用已有policy；不对所有频道做长时FFmpeg测试。尚未实现完整DASH片段解析和解密密钥/初始化片段全量遍历。

连接错误记为ENVIRONMENT_LIMITED，不因运行器网络受限永久移除。其他失败仍按原生命周期冷却；历史文件保留候选，后续可以恢复。分数在历史可用率、响应、画质及持续性基础上增加新鲜度和最近连续失败惩罚：score_freshness_days默认7天、recent_failure_penalty默认8分。缺测不会写成伪造画质或延迟。生产pipeline显式使用当前检测时间重新计算；旧calculate_score(history,policy)调用为确定性保持测量时评分。

验证：.venv/Scripts/python.exe -m pytest -q；目录发布后执行 iptv-manager validate-catalog --output-dir output。现有每日/每周Actions生成并校验新目录，Pages复制稳定路径、清单和全部版本目录。当前不构成真实授权直播源或电视设备体验的验收。

区域限制补充：当有真实连续HD媒体成功记录且最近成功不超过30天、此后只有ENVIRONMENT_LIMITED/HTTP_TIMEOUT/FIRST_BYTE_TIMEOUT时，新目录仍保留获授权来源作低分备源（最高40分，排在本轮已验证来源后）。environmentLimited=true、measurementStatus=historicalEnvironmentLimited；resolution/videoCodec/frameRate来自lastSuccess对应的历史成功样本，lastChecked对应本轮未知失败，不表示本轮重新测得这些媒体指标。真实HTTP错误、占位、无视频、错标和撤权会剔除；硬失败之后再遇超时也不会偷偷从旧发布恢复。

跨端互通样本在fixtures/channels-v1.json，仅使用*.example和合成指标，不是授权直播源，也不加入生产目录。该样本包含中文/emoji、null、29.97帧率及0.333333成功率以验证原始JSON数字保真；实际生成器目前将新测量数字规范为最多四位。客户端不得在验证摘要前再次舍入样本数字。固定摘要是6c32f768aa9170baa13e80fbc24344a38193f5d775500239ea3d27412013fe1e。
