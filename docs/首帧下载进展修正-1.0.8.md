# 1.0.8 首帧等待以实际下载进展判断

## 问题和修正

原逻辑从prepare或重新同步开始固定计时12秒。即使媒体分片正在持续下载、缓存正在增长，未出首帧仍会触发恢复，打断当前加载。

现在首帧/准备超时以最后一次媒体下载字节增长或已缓冲位置增长的时间为基准。下载和缓存继续增长时保留当前加载，不因累计等待超过12秒而重试。两者停止增长达到超时才继续原有恢复机制。真实内核播放错误仍按错误处理，不把已停止的内核当成仍在下载。

通过请求路径和Content-Type排除常见M3U8清单及文本请求；清单字节和媒体字节分开统计。总下载速度仍为真实网络字节速度。重新同步时以当前计数为基准，避免把旧下载量误认为新进展。

保留1.0.7对已播放线路普通缓冲的等待，以及曾播放线路自动回退。未设置或新增下载限速，未引入多分片并发，未修改画质或播放倍速。

## 验证

两个回归用例先复现失败：下载持续增长超过12秒、缓存持续增长超过12秒。另验证停止增长后仍能超时，以及媒体/清单计数分离。

新增Android实际网络测试：本地HTTP服务器将有效MP4的媒体头持续缓慢传输超过14秒，确保此时未出首帧；断言期间没有触发恢复，随后完成传输并实际出画面。该测试是本地受控播放，不能代表用户电视的远程源吞吐。

仍需用户电视验证真实线路连续播放质量，不能据此宣称远程源的一秒一缓冲已完全消失。
