# TCL 电视黑屏排查与隐藏诊断

1.0.3 用于收集电视的真实错误，尚未宣称修复本次黑屏。常规界面保持只有分类、频道与画面。

## 电视上拍照

覆盖安装1.0.3，打开智选直播，在黑屏或播放画面下长按遥控器确认键4秒，松开后出现“播放诊断 · 请拍照此页”。拍下整页。短按确认刷新，返回键继续看电视。

此页显示当前频道、正在尝试第几条线路、脱敏主机、首帧、已渲染帧、媒体格式、缓冲、恢复原因、Media3错误码及异常类型链；HTTP失败能显示状态码。异常原始消息、路径参数、令牌不进入快照或错误类型日志。

用户电视的文件管理器已显示Android/data“拒绝访问”，因此不再要求从文件管理器进入目录，也不尝试远程连接电视、提权或修改系统权限。日志仍由应用自动写入自己的Documents/diagnostics目录。

## 代理与直连核查

- 电脑没有HTTP_PROXY等环境变量，但有启用的FlClash Meta Tunnel，且同时存在隧道与WLAN默认路由。关闭httpx的trust_env不能排除透明网络隧道，之前成功采样和模拟器播放不能证明无代理直连成功。
- 默认路由下CCTV-1、CCTV-2、江苏和北京候选均返回HLS清单；GitHub Pages目录也返回200。这些结果仅代表当时电脑路由环境。
- 使用Windows `IP_UNICAST_IF`指定实际WLAN接口4，并绑定本机WLAN地址，再对74.91.26.218:82、107.150.60.122:80、204.12.221.218:8181各发起一次连接，均在6秒内未完成连接。没有关闭代理、修改路由或影响其他程序。
- 从同一WLAN接口向路由器DNS查询浙江卫视公开主机，得到36.155.131.35；保持TLS主机校验直连该地址，读取 `https://ali-m-l.cztv.com/channels/lantian/channel001/1080p.m3u8` 得到200和HLS清单。这只是清单连通性对照，不把它当成视频分片、解码或电视持续播放已经成功。

指定接口方法见[微软IPPROTO_IP套接字选项说明](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)。当前证据支持线路对直连网络不适配的可能性；尚需电视快照区分网络超时、重定向、HTTP错误和解码错误，不能把所有黑屏直接归因于VPN或电视。

GitHub Pages只分发JSON目录，不是视频服务器；APK自带目录快照，显示频道不证明目录网站或媒体上游在电视网络可达。本项目不要求客户安装VPN，也不能承诺每个海外或GitHub地址在所有宽带可直达。

## 验证

长按入口的设备测试先在旧版失败，再实现通过；另加错误类型摘要不泄露敏感消息的回归。Python全量160项、Android JVM28项、Android TV13项设备测试、构建和静态检查通过。本次没有修改频道候选或宣称已完成无代理源替换。
