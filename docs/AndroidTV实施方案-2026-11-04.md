# GitHub 调度与 Android TV 实施方案

## 现状与复用

复用 `src/iptv_manager` 中采集、频道匹配、HTTP/HLS 初筛、媒体复检、历史评分、生命周期和订阅发布。保留现有目录、每日/每周 Actions、原订阅地址和独立台湾试播。现有客户端是外部 LibreTV，仓库尚无 Android 客户端。本仓库未发现《NewTV架构分析与证据.md》；不复用其他应用的私有实现。

## 已明确的取舍

用户要求直接实施，不再等待设计确认。采用 Kotlin、原生电视 Views、Media3、OkHttp、本地偏好与文件缓存；不使用 Flutter、网页套壳、收费服务器、视频中转、账号和观看记录上传。主播放器最多一个，备用播放器最多一个、默认关闭预缓冲；默认仅做有界备用地址检查，避免低端盒子解码资源不足。

GitHub 作为静态目录和历史统计发布端；本机实际成功、缓冲、首帧和异常记录优先于 GitHub 分数。播放器使用有界恢复状态机，区分 READY 与首帧，使用多个信号判断疑似视频问题，不对静态电视画面做像素差黑屏判定。不承诺跨源无缝切换。

## 授权与发布协议

新 Android 目录必须有明确使用许可记录，历史社区 URL 不自动获准。尚无授权的频道不进入新目录，不能用旧源补数量；仍保留旧 M3U 接口兼容。配置支持 schemaVersion、minClientVersion、generatedAt、contentHash、频道及多条来源。规范摘要为 channels 数组的排序键、无空白、UTF-8 JSON 的 SHA256，数字字段统一跨语言规范。未知指标为 null，不虚构分辨率或性能。

发布版本化 JSON/M3U 配置包与最终原子清单指针，保留上一份；客户端 HTTP 条件请求、版本/体积/字段/摘要校验、损坏回退。正式目录可能为空，属于源授权缺失，不是编造测试结果的理由。应用内诊断彩条为自制媒体，不冒充直播频道。

## 开发与验证顺序

1. 服务端先补失败用例，再实现授权准入、多源目录、来源分组、评分时效、Schema 和一致性发布；跑完整 Python 回归。
2. 独立新增 `android-tv/`，建立真实 Gradle 构建、TV Launcher、遥控器列表、分类/搜索/收藏/最近和静态配置缓存。
3. 实现本地选源、首帧/缓冲监测、有限重试与隔离、网络恢复、资源释放、可配置缓冲、日志脱敏及文件导出；故障状态机使用受控时钟测试。
4. 运行 Android 单元测试、lint、assembleDebug，验证真实 APK。若模拟器可运行，安装并测试遥控器/离线画面/诊断；没有实体电视时明确未验证长期硬件播放与 NewTV 对照。

## 成功与限制

产出真实 Debug APK及安装命令；没有正式签名不伪造 Release 签名。不能宣称达到 NewTV 水平，不能将 GitHub 节点探测等同于电视观看体验。当前无连接的实体电视，生产频道许可也尚未提供；这些不阻止代码、受控测试和 APK 构建，但阻止真实电视长时间体验验收及大规模频道内置。
